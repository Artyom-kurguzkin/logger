# 25 Nov — spike result, every point works

An extension as a stdio MCP server with an MCP App panel works in Photino, in a debug build and in the published single-file exe. The SDK (ModelContextProtocol 2.4.0) sends and handles custom `aklogger/*` methods, so the fallback of hidden `_aklogger_` tools is not needed.

What #wi4 has to follow (details in the plan, section "Spike findings"):

- The server-side custom-method API is experimental (`MCPEXP002`).
- The host must add `frame-src http://127.0.0.1:<port>` to its page CSP; the port is only known after Kestrel binds.
- A child that ignores the end of stdin survives a hard kill of the host: the Windows Job Object is required.
- Photino needs an STA `Main`.

The code is throwaway, in `spike/`; the run logs are `spike/out/dev/result.log` and `spike/out/dist/result.log`.
